# 本机与远程排查流程

先记录正在运行的版本、安装目录、游戏启动平台、故障时间和界面错误。不要在对局中重启加速器、调整网卡或移动目录。

## 克隆后首次运行

1. 克隆源码，执行 `build/Compile-App.ps1` 和 `tests/Test-Offline.ps1`。此时只验证界面和本地逻辑。
2. 按 [依赖说明](DEPENDENCIES.md) 准备官方 SDK、PowerShell 运行时，并在新电脑本机导入独立设备密钥。
3. 在设置中填写本机实际存在的 Steam、WeGame 路径。最多保存两个；运行哪个进程，就匹配哪个完整路径。
4. 在游戏不处于对局时开启加速，核对界面版本与连接状态，再测试一次实际入局。记录游戏内延迟及入口结果，区分“线路已连接”和“游戏确实发送了命中规则的解析请求”。

旧电脑的 DPAPI 密钥文件不能作为新电脑的配置迁移方案，也不要将本机运行记录提交到 GitHub。

## 连接动画持续或阶段没有变化

记录界面显示的当前阶段、本次已耗时和错误文字。连接动画表示启动任务正在处理，阶段来自后台状态；动画仍在动不代表阶段已推进。成功状态需要后台实际确认就绪。

上次成功耗时只是一条历史参考。超过该时长不能单独证明本次失败，也不表示还需等待固定秒数；没有历史记录时，不应凭空推定预计完成时间。若出现明确错误，按该错误定位问题，避免只依据动画或历史耗时反复重连。

## 重启后提示仍在运行或需要恢复

Windows 重启后，保存的运行记录与当前进程可能不一致。排查需要同时核对当前进程路径、进程创建时间、监听端口、虚拟网卡和该次运行的归属记录。

如果原客户端仍能打开，优先使用“关闭并恢复”，等待完成后退出。不要仅凭旧 PID 或一个 JSON 文件直接杀进程，也不要在未核对资源归属时清空恢复记录、全局重置 DNS/路由或删除所有防火墙规则。

本修复分支先判断会话是否来自上次系统启动，再核对本次进程路径。确认旧会话已结束且无 SDK、专属 TUN 或控制端口占用时，开启和关闭入口都会归档旧记录。旧 PID 不作为清理依据；当前仍有残留时保留错误并阻止接管。离线回归通过不等于所有现场重启情形已经验证，详见 [会话恢复说明](SESSION_RECOVERY.md)。

## 移动安装目录或更换启动入口

先在原安装目录正常停止加速并退出客户端，再处理目录迁移或快捷方式。核对快捷方式目标、工作目录及实际运行的 `Accelerator.exe` 路径，避免打开旧副本。

运行记录可能保留旧的绝对路径。不要把整个 `backend/private` 或 `backend/results` 从旧目录直接覆盖到新克隆目录；其中不仅有恢复信息，还可能包含设备密钥。需要保留密钥时，使用应用既有导入方式，并保持同一获授权用户和设备的边界。

MSIX 可能只重定向文件而不重定向父目录。本分支根据 Common 脚本文件句柄的实际路径定位配套后端，并以实际文件路径和精确创建时间核对 worker；不能只比较父目录或文件内容哈希。上次系统启动的旧目录记录可按归档流程恢复；本次启动内无法证明归属的目录变化仍会被拒绝，不自动接管未知进程。

## 有线与 Wi-Fi 切换

在停止加速后切换网络，再重新开启，便于建立当前网络基线。有线反复断开只能提示链路、接口或网卡侧问题，不能仅凭应用日志断言网线损坏；应结合 Windows 网络事件、网卡状态和网关丢包分开判断。

入口解析失败、应用恢复状态错误和对局延迟是不同观测结果，应分别记录时间与证据。界面报错文本现使用 UTF-8 输出，仍应保留完整错误文字以便定位。

## 停止后出现 IPv6 恢复差异

1.0.4 会识别物理网卡上可确认由路由通告（RA）自动生成的 ULA 地址增减，并核对同侧变化中与该地址、网卡精确对应的 `Local /128` 路由。例如，被移除路由必须对应同次比较中被移除的自动地址，不能用另一侧新增地址作依据。

这项判定只解释特定的自动地址变化，不改写网卡、地址或路由，完整差异仍保留在本机报告。无法确认来源的路由、手工配置、DNS、默认路由和 TUN 配置差异仍会提示核对；它不代表所有 IPv6 恢复误报都已解决。

## 分享可复核的信息

可提供源码提交号、程序版本、发生时间、启动平台、连接阶段与已耗时、脱敏错误及离线测试通过/失败数量。原始密钥、SDK 认证响应、设备标识、局域网地址、用户目录和游戏日志中的令牌应留在本机；需要日志时先进行定向脱敏。
