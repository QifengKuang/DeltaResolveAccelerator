# 会话恢复规则与验证

此分支基于 1.0.4。修复 Windows 重启后旧的 connected 记录仍被显示，以及 MSIX 逐文件重定向导致后台和归属记录使用不同安装路径的问题。Steam/WeGame 双路径、真实进度阶段、操作计时、UTF-8 和现有 IPv6 差异判定保留。

## 当前状态的依据

- 以 Common 脚本文件句柄的最终路径定位后端，而不是仅解析父目录。不同实体副本不会仅因文件哈希相同就被视为同一安装。
- worker、ownership、status 保存相同的系统启动标记及会话编号。兼容旧记录中的创建时间，但混合新旧启动的记录拒绝接管。
- 已连接需要匹配当前会话、存活 worker、精确创建时间、实际程序路径，以及不超过 30 秒的已就绪状态。PID 被复用、会话错配或状态过期均不显示已就绪。
- 创建进程前的 PID=0 发布窗口最多 5 秒，始终不表示已就绪。当前有效操作保留 1.0.4 的进度与计时；旧会话和已退出后台不再显示旧动画进度。

## 上次系统启动的记录

Start 和 Stop 都在控制锁内先处理旧启动记录，再检查旧路径。仅当没有 SDK/helper、`mna_game_*` / `mp_tun0` 网卡，也没有 9801、12345、9803 的 TCP/UDP 占用时才归档。过程不终止旧 PID，不重置网络，也不使用上次启动的接口索引比较当前网络。

归档只保存已知会话元数据。按归档、终止 owner、终止 worker 指针、stopped 状态的顺序写入；中途写入失败时下次动作可以继续。密钥与其他私有文件不复制到归档。当前恢复检查失败保留当前错误；不会用“旧会话已结束”覆盖失败原因。

本次系统启动内的未知进程、不同实体安装路径、错误会话编号或不一致时间仍需核对，不能为了显示成功跳过归属检查。

## 验证

运行 `build/Compile-App.ps1` 和 `tests/Test-Offline.ps1`。完整离线套件包括后端规则、原子写入、UI、会话分类及真实 Control 入口的模拟 Start/Stop。模拟覆盖重启前已连接、旧目录、进程异常退出、PID 复用、归档写入中断、残留阻塞、状态过期和进度字段保留。测试不连接云服务或启动真实 SDK。

部署时应正常停止当前加速器，备份将替换的自有程序与脚本，以文件哈希核对正式安装；现有本机 DPAPI 密钥、设置和运行依赖留在原处。实际连接验证还需核对当前启动时间、会话编号、进程创建时间与路径、监听及专属 TUN，最后确认正常关闭恢复。

离线模拟以及一次实际开启/关闭不能证明所有重启、快速启动或网络切换场景。若需要完成真实重启验收，应先正常退出游戏和加速器，按用户安排重启系统，再验证初始未连接、正常开启、持续状态刷新和正常关闭。未经用户安排不自动重启，也不承诺永不复发。

测试输出、实际部署记录、网络与游戏日志只保留本机，不提交仓库。
